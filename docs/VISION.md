# prou5t — 回忆助手

## 一句话

> 用户说话，Agent 倾听，把回忆变成日记，让记忆可检索、可回溯、可再生成。

## 为什么做这个

人的记忆是衰减的。过去的经历、曾经的故事、久远的念头，如果不记下来，就消失了。

现有的日记工具需要用户主动去写，门槛高、难坚持。而人在对话中自然地回忆和讲述——我们想把这个过程变成日记。

**核心假设：对话是最低成本的回忆输入方式。**

**关键约束：只有回忆性内容才会被记录为日记。** 用户讲述的内容必须是某个时间段之前的往事，当天的内容不算——哪怕是下午聊上午的事也不算。Agent 需要判断内容的"时间距离"，只有跨天的回忆才有资格成为日记。

## 要做成什么

一个 CLI 对话助手，具备三个核心能力：

### 1. 日记提取

用户在对话中**回忆往事**。Agent 识别这些内容，提炼为结构化日记，持久化存储。

- **只有回忆性内容才提取**：讲述的必须是过去的事（跨天以上），当天的事情不记录
- 不是逐句记录，而是等一段讲述完成后提炼
- 日记包含：事件时间（用户回忆的那个时间）、记录时间（提取时间）、内容、人物、地点、情感、标签
- 用户可以修改、补充、确认

### 2. 日记检索

用户可以用自然语言查询历史日记。

- "去年夏天我讲了什么？"
- "关于奶奶的日记有哪些？"
- "2026年5月的日记"

支持关键词检索和语义检索。

### 3. 记忆系统

Agent 拥有跨会话的记忆能力，记住用户的偏好、习惯、重要事实。

- 记忆 ≠ 日记：记忆是对话历史的压缩，日记是目标产物
- 记忆通过 Hook 机制注入上下文，不影响主对话流
- 压缩策略待定，参考其他项目后决定

## 不做什么（现阶段）

- 不做 Web UI / 移动端
- 不做多用户系统
- 不做社交分享
- 不做实时语音

## 成功标准

1. 用户能自然地对话，Agent 能准确识别"回忆"并提炼为日记
2. 日记可被语义检索，检索结果相关且完整
3. Agent 跨会话保持记忆连续性，知道"你是谁"
4. 数据完全本地存储，用户拥有绝对控制权

## 项目哲学

- **文档先行**：所有需求、设计、决策先落盘为文档，再动手写代码
- **渐进复杂**：从最简单的可用版本开始，逐步增加能力
- **可替换**：用框架快速验证业务逻辑，后期可替换为自研实现
