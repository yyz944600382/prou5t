# D003 — 记忆与日记的边界

## 上下文

系统中有两个容易混淆的概念：记忆（Memory）和日记（Diary）。需要明确边界。

## 决策

| | 日记 (Diary) | 记忆 (Memory) |
|---|---|---|
| **本质** | 目标产物 | 辅助机制 |
| **来源** | 从用户回忆中提炼 | 从对话历史中压缩 |
| **结构** | 完整叙述，包含人物/地点/情感/标签 | 摘要 + 关键事实 + 用户画像 |
| **用途** | 被检索、被阅读、被再生成 | 注入上下文，维持对话连续性 |
| **生命周期** | 永久，用户可删除 | 分层衰减（工作/短期/长期） |
| **存储** | SQLite + 向量索引 | SQLite |

### 关系

```
对话 → 日记提取 → 日记存储
                  ↓
对话 → 记忆压缩 → 记忆存储 → 下次对话时注入上下文
```

日记和记忆独立存储，但日记可以反哺记忆（如日记中的关键人物进入长期记忆）。

## 后果

- 两套独立的存储和检索逻辑
- 日记提取和记忆压缩是两个独立的 Hook，互不依赖
