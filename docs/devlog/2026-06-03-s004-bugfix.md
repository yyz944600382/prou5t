# Devlog — S004 Bug 修复

## 问题

S004 关键词检索有 41 个测试失败（93 总），根本原因 3 个：

### Bug 1：FTS5 中文分词完全失败

**现象**：所有中文搜索返回 0 结果
**原因**：FTS5 `unicode61` tokenizer 把连续中文当作单个 token。"海边旅行" 是一个 token，搜 "海" 或 "海边" 都匹配不到
**修复**：新增 `src/search/tokenizer.ts`，应用层字符级分词。注册 `tokenize_chinese` 自定义 SQL 函数，触发器插入 FTS5 时自动分词："海边旅行" → "海 边 旅 行"

### Bug 2：FTS5 content= 外部内容模式同步不可靠

**现象**：INSERT/UPDATE 触发器部分失败，DELETE 触发器失败
**原因**：`content='diaries'` 模式下 FTS5 从主表读内容，与触发器的同步机制有冲突
**修复**：去掉 `content='diaries'` 和 `content_rowid='rowid'`，改为独立 FTS5 虚拟表。UPDATE 触发器改为 DELETE+INSERT（而非 UPDATE SET）

### Bug 3：测试文件共享数据库互相干扰

**现象**：单独跑某个测试文件通过，一起跑就失败
**原因**：测试设置 `process.env.DATABASE_PATH=":memory:"` 但 `initDatabase()` 不读这个变量，所有测试写同一个 `data/prou5t.db`
**修复**：`initDatabase(":memory:")` 支持内存数据库参数

## 额外修复

- 高亮标记从 `{ }` 改为 `\x01 \x02`（不与正常文本冲突）
- 查询构建器 `buildFTSQuery` 重写为 `buildTokenizedFTSQuery`，支持中文 AND/OR/前缀查询
- 测试代码修正：`diaryRepo.save()` 返回 `string` id，不是 DiaryEntry 对象，修 `diary.id` → `diaryId`
